leetcode.txt        LeetCode client

INTRODUCTION                                            *leetcode*

This plugin makes it possible to solve LeetCode problems in Vim.

COMMANDS                                                *leetcode-commands*

                                                        *:LeetCodeList*
:LeetCodeList       List all the problems: how many you solved, the
                    difficulty and status filters, topics and companies
                    (folded), and the table, with the cursor on the first
                    problem (see |leetcode-mappings|). Opening a problem
                    hides the list and shows the description and the code
                    side by side; :LeetCodeList brings the list back.

                                                        *:LeetCodeOpen*
:LeetCodeOpen {problem}
                    Open a problem by its number or slug, e.g.
                    `:LeetCodeOpen 1` or `:LeetCodeOpen two-sum`. <Tab>
                    completes slugs. An empty window is reused.

                                                        *:LeetCodeTest*

:LeetCodeTest       Run the solution against test cases. A window opens with
                    all the problem's examples, one argument per line and a
                    blank line between cases; edit them or add your own,
                    then save and close it (|:wq|), or run :LeetCodeTest
                    again in it, to start the run. |:q!| cancels. The cases
                    are kept for the next run. The result shows the verdict
                    and each case: its input, your output, the expected one
                    and what your code printed, failed ones marked and
                    highlighted (the window scrolls to the first).

                                                        *:LeetCodeSubmit*
:LeetCodeSubmit     Submit the solution.

:LeetCodeTest and :LeetCodeSubmit work from the solution file or from any
window that belongs to it: its description, the test input or the result.

                                                        *:LeetCodeSignIn*
:LeetCodeSignIn     Sign in, or replace the saved cookie (e.g. to switch
                    accounts). See |leetcode-sign-in|.

                                                        *:LeetCodeSignOut*
:LeetCodeSignOut    Sign out and forget the saved cookie.

                                                        *:LeetCodeReset*
:LeetCodeReset      Reset the code in the current buffer to the initial code
                    template.


THE DESCRIPTION WINDOW                                  *leetcode-description*

Opening a problem shows its description above the solution, as a Markdown
buffer ('filetype' markdown, so Markdown plugins such as render-markdown.nvim
apply): the title, difficulty, acceptance, likes and topics, a link to the
problem, the description with its examples as code blocks, the hints (folded
until you open them, as they give the solution away) and similar questions.
<CR> on a similar question opens it; on the closed Hints fold, it opens the
fold.

SIGNING IN                                              *leetcode-sign-in*

LeetCode has no API tokens, and its login page uses a CAPTCHA, so the plugin
signs in with the session cookie of a browser where you are signed in to
LeetCode. By default it asks for that cookie the first time it needs it:

1. Sign in to LeetCode in your browser.
2. Open the developer tools (F12), then the Network tab, and reload the page.
3. Click any request to leetcode.com and copy the value of its "Cookie"
   request header, or just the value of the LEETCODE_SESSION cookie
   (Application/Storage tab, Cookies).
4. Paste it at the prompt. Nothing is shown while you paste.

The plugin keeps only the LEETCODE_SESSION cookie, in a file that only you
can read (see |g:leetcode_cookie_file|). The CSRF token LeetCode also wants
for running and submitting code is not stored: the plugin gets one when it
signs in, and a new one if LeetCode turns it down. When the session
expires, it asks again. See |g:leetcode_browser| for other ways to provide
the cookie.

MAPPINGS                                                *leetcode-mappings*

These mappings are available in the problem list buffers.

                                                        *leetcode-<CR>*
<CR>                Open the problem under the cursor or list the problems of
                    the topic or company under the cursor. On the closed
                    Topics or Companies fold, open it (|zo| and |zc| work too;
                    a fold stays open when the list is redrawn).

                                                        *leetcode-f*
f                   Show only the problems whose title contains the text you
                    type (ignoring case), or the problem with that number.

                                                        *leetcode-F*
F                   Show all problems again.

                                                        *leetcode-s*
s                   List the submissions of the problem under the cursor,
                    in place of the problem list: when, status, language,
                    runtime and memory. <CR> there opens one next to the
                    list, with how it did in a comment above its code
                    (opening another replaces it); r refreshes; q goes back
                    to the problem list. :LeetCodeSubmit in a submission
                    sends its code without that comment.

                                                        *leetcode-r*
r                   Refresh the problem list (redownloading all the contents).

                                                        *leetcode-S*
S                   Sort the problem list. The command will prompt users to
                    choose the column to be sorted and the sorting order.

                                                        *leetcode-t*
t                   Choose the time period of the frequency to show. This
                    command is only available in the company problem list.

In the list, ✓ marks solved problems and ~ attempted ones (X and ? when
'encoding' isn't UTF-8). A test run says Accepted or Wrong Answer; only a
submission changes a problem's mark.

HIGHLIGHTS                                              *leetcode-highlights*

The plugin's colors are defaults, so you can set your own after it loads or
in your colorscheme, e.g. `highlight lcHard ctermfg=203`. Neovim links them
to the diagnostic groups; Vim picks colors that suit 'background'.

    lcEasy lcMedium lcHard      difficulty in the list
    lcDone lcTodo               solved and attempted marks
    lcPaidOnly                  [P] after paid-only titles
    lcAccepted lcFailure        the verdict in results
    lcMismatch                  answer lines that differ from the expected
                                ones (DiffText)


CUSTOMIZATIONS                                       *leetcode-customizations*

                                                        *g:leetcode_china*
g:leetcode_china    Set it to 1 to login to a LeetCode China (leetcode.cn)
                    account.

                    Default: 0

                                                      *g:leetcode_base_url*
g:leetcode_base_url The LeetCode site to use, e.g. "https://leetcode.cn".
                    Overrides |g:leetcode_china| when set.

                    Default: ''

                                                      *g:leetcode_backend*
g:leetcode_backend  How the plugin talks to LeetCode:
                    "vim"      through Vim script and curl, no Python needed.
                               It does not read cookies from a browser's
                               store ("chrome", "firefox").
                    "python"   through autoload/leetcode.py. Needs Vim with
                               +python3 (Neovim: pynvim) and the requests
                               package.

                    Default: "vim", or "python" when |g:leetcode_browser|
                    is "chrome" or "firefox"

                                                      *g:leetcode_browser*
g:leetcode_browser  Where the LeetCode session cookie comes from:
                    "paste"    ask for it, see |leetcode-sign-in|.
                    "chrome", "firefox"
                               read it from the browser's cookie store
                               (needs the browser-cookie3 and keyring
                               Python packages).
                    "env"      read $LEETCODE_SESSION.

                    Default: "paste"

                                                    *g:leetcode_cookie_file*
g:leetcode_cookie_file
                    Where pasted cookies are saved. Default: "leetcode.vim/
                    cookies.json" under stdpath("data") in Neovim, and under
                    $XDG_DATA_HOME (or ~/.local/share, or %LOCALAPPDATA% on
                    Windows) in Vim.

                                              *g:leetcode_solution_filetype*
g:leetcode_solution_filetype
                    The language to use to solve LeetCode problems.

                    Default: "cpp"
                    Values: "cpp", "java", "python", "python3", "csharp",
                            "javascript", "ruby", "swift", "golang", "scala",
                            "kotlin", "rust"

                                                  *g:leetcode_solution_dir*
g:leetcode_solution_dir
                    Where solution files are saved, e.g. 1.two_sum.cpp. A new
                    solution (the template, or your latest submission in
                    that language) is written there as soon as you open the
                    problem; an existing file is opened as it is, so your
                    work is never replaced (|:LeetCodeReset| starts over).
                    An empty string means the current directory.

                    Default: "~/leetcode"

                                                  *g:leetcode_hide_paid_only*
g:leetcode_hide_paid_only
                    Hide the paid only problems on the list.

                    Default: 0

                                                     *g:leetcode_hide_topics*
g:leetcode_hide_topics
                    Hide the topics section.

                    Default: 0

                                                  *g:leetcode_hide_companies*
g:leetcode_hide_companies
                    Hide the companies section.

                    Default: 0

                                                      *g:leetcode_problemset*
g:leetcode_problemset
                    Set the problemset to get from leetcode.

                    Default: 'all'
